# 기능 명세서

## 개요
- **프로젝트명**: AI UI/UX 디자인 아카데미 소개 홈페이지 + 정원 신청 시스템 + 멘토 자동 매칭 시스템 (국비지원은 부가 혜택으로 안내)
- **현재 단계**: 프론트엔드(React + Vite) 프로토타입 완성, mock data + Context API 기반. 배포: https://ui-ux-course-site.vercel.app
- **기술 스택**: React 19 + React Router 7 + Vite (Frontend). 백엔드(Node.js + Express + SQLite)는 기획만 되어 있고 아직 미구현 — 현재 모든 데이터는 브라우저 메모리(Context API state)에만 존재하며 새로고침 시 초기화된다.

## 사용자 유형 및 권한

| 유형 | 인증 | 역할 | 테스트 계정 |
|---|---|---|---|
| 지원자/수강생 | 회원가입/로그인 | 과정 조회, 지원, 마이페이지, 멘토 상담 신청 | minji@example.com / 1234 |
| 멘토 | 로그인 (role=mentor) | 배정된 상담 수락/거절/완료 처리 | jisu@example.com / 1234 |
| 관리자 | 로그인 (role=admin) | 지원자·정원·멘토 매칭 관리 | admin@example.com / 1234 |

인증은 `src/context/AuthContext.jsx`에서 mock 계정 배열(`src/data/users.js`)로 처리한다. 로그인 상태만 `localStorage`에 유지되고, 회원가입으로 새로 만든 계정은 새로고침 시 사라진다(의도된 동작).

역할별 라우트 보호는 `src/components/RequireAuth.jsx`가 담당한다:
- 비로그인 상태로 보호된 라우트 접근 → `/login`으로 리다이렉트
- 로그인했지만 요구 role과 다름 → "접근 권한이 없습니다" placeholder 표시

## 핵심 비즈니스 로직

### 1. 정원 초과 방지 + 관리자 수동 심사 (`src/context/ApplicationContext.jsx`)
- 멘토 상담을 완료한 지원자만 지원 가능(하드 게이트, `CourseDetail.jsx`). 지원 접수 시 정원과 무관하게 항상 `pending`(심사중)으로 들어오며, 합격/불합격은 관리자가 수동으로 결정
- 상태 전이: `pending` → `confirmed` / `rejected` / `waiting` → `cancelled` (재지원은 `cancelled`/`rejected` 상태에서만 허용)
- 관리자가 드롭다운으로 "합격(confirmed)"으로 바꾸려는 시도는 정원 체크를 거친다 (2026-07-31 테스트에서 발견된 정원 초과 버그를 수정하며 추가된 가드)

### 2. 대기열 승격 — 관리자 수동 처리 (2026-08-06 변경)
- 확정 좌석이 비어도(취소 또는 관리자 상태 변경으로 confirmed → 다른 상태) 대기(waiting) 지원자를 자동으로 승격하지 않는다 — 관리자가 대기중인 지원자를 직접 "합격"으로 변경해야 한다
- 빈 자리는 `/course` 지원 현황 배너·관리자 대시보드 요약 통계의 "남은 자리" 수치로 실시간 확인 가능
- 자기 취소(마이페이지)와 관리자 상태 변경이 동일한 `updateApplicationStatus` 함수를 공유 (변경 전에는 이 함수가 자동 승격까지 함께 처리했으나, 지금은 상태 변경만 수행)

### 3. 멘토 자동 매칭 (`src/context/ConsultationContext.jsx`)
- 상담 분야가 일치하고 아직 여유(현재 부하 < 최대 동시 처리 수)가 있는 멘토 중 부하가 가장 적은 멘토에게 자동 배정
- 배정 가능한 멘토가 없으면 `requested` 상태로 남아 관리자 수동 배정 대기
- 상태 전이: `requested` → `matched` → `in_progress` → `completed`
- 멘토가 거절하면 배정을 풀고 동일 로직으로 재매칭을 시도, 실패하면 다시 `requested`로 전환(관리자 모니터링에 노출)

## 알려진 제약 사항 (2026-07-31 기준)
- **백엔드 없음**: 모든 상태는 브라우저 세션(React state) 안에만 존재. 페이지를 새로고침하거나 다른 브라우저/탭에서 열면 seed data로 초기화된다. 여러 사용자가 실제로 "동시에" 마지막 좌석에 신청하는 경쟁 상황은 현재 구조로는 재현·방지가 의미 없음 — 백엔드(SQLite) 도입 후 트랜잭션 단위로 재검증 필요.
- **회원가입 미영속**: `register()`로 만든 계정은 메모리 배열에만 추가되어 새로고침하면 사라진다.
- **관리자가 mentor role 페이지 접근 불가**(그 반대도 동일) — `RequireAuth`가 role을 정확히 일치시키는 설계이므로 의도된 동작.
