# 기능 명세서

## 개요
- **프로젝트명**: AI UI/UX 디자인 아카데미 소개 홈페이지 + 정원 신청 시스템 + 멘토 자동 매칭 시스템 (국비지원은 부가 혜택으로 안내)
- **현재 단계**: 프론트엔드(React + Vite) + 백엔드(Supabase) 연동 완료. 회원 인증・지원・상담・비회원 콜백・커뮤니티・문의・학원 일정 7개 도메인이 실제 데이터베이스에 저장되며, 새로고침・재접속해도 유지된다. 공지사항・강사진・멘토 소개・수료생 후기・포트폴리오・파트너사・FAQ는 아직 코드(`src/data/*.js`)에 정적으로 있어 관리자가 화면에서 직접 수정할 수 없다(변경하려면 코드 수정 필요).
- **배포**: https://ui-ux-course-site.vercel.app (Vercel)
- **기술 스택**:
  - Frontend: React 19 + React Router 7 + Vite 8
  - Backend: Supabase(PostgreSQL + Auth + Row Level Security). 이 프로젝트 전용 `academy` 스키마를 사용(같은 Supabase 프로젝트를 다른 앱과 공유하기 때문에 `public` 스키마 대신 분리).
  - DB 스키마와 정책은 `supabase/migrations/*.sql`에 순서대로 기록되어 있고, Supabase 대시보드 SQL 에디터에서 순번대로 실행해 반영한다(CLI 연동 없이 수동 실행).

## 사용자 유형 및 권한

| 유형 | 인증 | 역할 | 테스트 계정 (비밀번호 공통 123456) |
|---|---|---|---|
| 지원자/수강생 | 회원가입/로그인 | 과정 조회, 지원, 마이페이지, 멘토 상담 신청, 커뮤니티/문의 게시판 이용 | minji@example.com |
| 멘토 | 로그인 (role=mentor) | 배정된 상담 수락/거절/완료 처리 | jisu@example.com |
| 관리자 | 로그인 (role=admin) | 지원자·정원·멘토 매칭·문의·학원 일정 관리 | admin@example.com |

인증은 `src/context/AuthContext.jsx`가 Supabase Auth(`supabase.auth.signUp`/`signInWithPassword`)로 직접 처리한다. 회원가입 시 입력한 부가 정보(이름・생년월일・성별・휴대폰・주소)는 `academy.profiles` 테이블에 별도 저장되며(비밀번호 자체는 Supabase Auth가 해싱해 관리), 로그인 세션은 Supabase가 브라우저에 유지하므로 새로고침해도 로그인 상태가 풀리지 않는다. 회원가입으로 만든 계정도 실제 DB에 영구히 남는다.

세션 복원은 비동기라 로그인 여부를 즉시 알 수 없다 — `AuthContext`의 `loading` 상태가 `true`인 동안은 `RequireAuth`가 아직 판단을 보류하고(깜빡임 방지), 복원이 끝난 뒤 최종적으로 로그인 여부를 확인한다.

역할별 라우트 보호는 `src/components/RequireAuth.jsx`가 담당한다:
- 비로그인 상태로 보호된 라우트 접근 → `/login`으로 리다이렉트
- 로그인했지만 요구 role과 다름 → "접근 권한이 없습니다" placeholder 표시

## 핵심 비즈니스 로직

### 1. 정원 초과 방지 + 관리자 수동 심사 (`src/context/ApplicationContext.jsx`, 테이블: `academy.applications`)
- 지원 접수 시 정원과 무관하게 항상 `pending`(심사중)으로 들어오며, 합격/불합격은 관리자가 수동으로 결정
- 상태 전이: `pending` → `confirmed` / `rejected` / `waiting` → `cancelled` (재지원은 `cancelled`/`rejected` 상태에서만 허용)
- 관리자가 "합격(confirmed)"으로 바꾸려는 시도는 매번 정원 체크를 거친다
- 모든 상태 변경은 Supabase에 즉시 반영되고, 변경 직후 서버에서 최신 값을 다시 조회해 화면에 반영한다(로컬 캐시가 실제 값과 어긋나지 않도록)

### 2. 대기열 승격 — 관리자 수동 처리
- 확정 좌석이 비어도 대기(waiting) 지원자를 자동으로 승격하지 않는다 — 관리자가 직접 "합격"으로 변경해야 한다
- 자기 취소(마이페이지)와 관리자 상태 변경이 동일한 `updateApplicationStatus` 함수를 공유

### 3. 멘토 수동 매칭 (`src/context/ConsultationContext.jsx`, 테이블: `academy.consultations`)
- 상담 신청은 항상 `requested`로 접수되고, 관리자가 신청 내용을 확인해 담당 멘토를 수동으로 배정한다(자동 매칭 없음)
- 상태 전이: `requested` → `matched` → `in_progress` → `completed`
- 멘토가 거절하면 배정을 풀고 `requested`(관리자 재배정 대기)로 되돌린다

### 4. 커뮤니티 게시판 (`src/context/CommunityContext.jsx`, 테이블: `academy.community_posts`・`community_comments`)
- 로그인 회원 누구나 글・댓글을 쓸 수 있는 다대다 자유 게시판(문의 게시판과 달리 관리자만 응답하는 구조가 아님)
- 글・댓글 모두 **작성자 본인 또는 관리자만** 수정・삭제 가능(Supabase RLS로 서버 단에서도 강제)
- 댓글은 글이 삭제되면 함께 삭제된다(`on delete cascade`)

### 5. 문의 게시판 (`src/context/InquiryContext.jsx`, 테이블: `academy.inquiries`)
- 1:1 답변형 — 로그인 없이도 이름/연락처/이메일만으로 문의 등록 가능(비회원은 계정이 없어 이후 재조회 불가, 담당자가 남긴 연락처로 직접 안내)
- 답변은 관리자가 1건만 등록 가능. 별도 상태 컬럼 없이 `reply_content` 유무로 답변대기/답변완료를 파생시켜 상태 불일치를 방지
- 로그인 회원은 본인 문의만 마이페이지/`/inquiry`에서 조회 가능

### 6. 학원 일정 관리 (`src/context/ScheduleContext.jsx`, 테이블: `academy.schedule_events`)
- 관리자가 모집・수업・행사 일정을 추가・수정・삭제하면 `/schedule`(월별 캘린더, 전체 공개)에 즉시 반영되고 DB에 영구 저장된다
- 공휴일 데이터(`src/data/holidays.js`)는 정적 데이터로 별도 관리(수업일 계산에만 사용, DB 미연동)

### 7. 비회원 콜백 신청 (`src/context/CallbackContext.jsx`, 테이블: `academy.callback_requests`)
- 로그인 여부와 무관하게 이름・연락처・문의 내용만으로 신청 가능한 리드(lead) 성격의 기능
- 관리자가 연락 완료 여부(`contacted`)와 담당 멘토를 수동으로 지정

## 알려진 제약 사항 (2026-08-12 기준)
- **관리자가 직접 관리할 수 없는 콘텐츠**: 공지사항・강사진・멘토 소개・수료생 후기・포트폴리오・파트너사・FAQ는 전부 `src/data/*.js`에 정적으로 있어, 내용을 바꾸려면 코드 수정과 재배포가 필요하다. 지원/상담/커뮤니티/문의/학원 일정처럼 관리자 화면에서 직접 CRUD하는 구조가 아니다.
- **RLS는 데모 목적으로 단순화됨**: 상태 변경(지원 합/불합, 상담 배정, 답변 등록, 학원 일정 CRUD 등)은 실제로는 관리자 전용 기능이지만, Supabase Row Level Security 정책은 "로그인한 회원이면 누구나 가능"으로 단순화되어 있고, 화면(라우트) 단에서만 role을 구분한다(민감 정보를 다루는 실서비스가 아니라는 전제). 글/댓글 수정・삭제만 "본인 또는 관리자"로 서버 단에서도 강제된다.
- **관리자가 mentor role 페이지 접근 불가**(그 반대도 동일) — `RequireAuth`가 role을 정확히 일치시키는 설계이므로 의도된 동작.
- **개인정보처리방침 미작성** — `/privacy`는 아직 placeholder.
