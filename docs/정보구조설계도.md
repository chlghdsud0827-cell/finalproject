# 정보 구조 설계도 (IA)

기획 초반에는 "로그인 → 지원자/멘토/관리자 3개 영역"이라는 큰 틀만 잡았는데, 실제로 페이지를 하나씩 붙여가면서 지금 형태로 자리를 잡았다. 아래는 현재 사이트(`src/App.jsx` 기준 26개 라우트)를 실제 구조 그대로 정리한 것이다.

## 전체 구조

```
AI UI/UX 디자인 아카데미
│
├─ 홈 (/)
│
├─ 교육과정
│  ├─ 과정 소개 (/course)
│  ├─ 국비지원 안내 (/funding)
│  ├─ 수료생 포트폴리오 (/portfolio)
│  ├─ 수강생 후기 (/reviews)
│  ├─ 취업지원 (/career-support)
│  └─ 채용연계 파트너사 (/partners)
│
├─ 소통공간
│  ├─ 자주 묻는 질문 (/faq)
│  ├─ 문의하기 (/inquiry)              ← 비회원도 작성 가능
│  ├─ 커뮤니티 (/community)
│  │   └─ 글 상세 (/community/:postId)
│  └─ 공지사항 (/notices)
│      └─ 공지 상세 (/notices/:noticeId)
│
├─ 학원안내
│  ├─ 학원소개 (/about)
│  ├─ 학원 연혁 (/history)
│  ├─ 교육시설 소개 (/facilities)
│  ├─ 강사진 소개 (/instructors)
│  ├─ 멘토 소개 (/mentors)
│  ├─ 학원 일정 (/schedule)
│  ├─ 오시는 길 (/location)
│  └─ 다른 지점 안내 (/branches)
│
├─ 로그인 / 회원가입 (/login)
│
├─ 회원 전용 (로그인 필요)
│  ├─ 마이페이지 (/mypage)
│  │   ├─ 지원 현황 탭
│  │   ├─ 상담 현황 탭
│  │   ├─ 문의 내역 탭
│  │   └─ 커뮤니티(내 글・댓글) 탭
│  └─ 상담 신청 (/consultation)
│
├─ 멘토 전용 (role=mentor)
│  └─ 멘토 대시보드 (/mentor)
│
├─ 관리자 전용 (role=admin)
│  └─ 관리자 대시보드 (/admin)
│      ├─ 요약
│      ├─ 지원자 관리
│      ├─ 강사・멘토 (조회 전용)
│      ├─ 상담 관리 — 정규 상담 매칭 모니터링 + 비회원 콜백 신청 관리
│      ├─ 문의 관리
│      └─ 학원 일정
│
└─ 개인정보처리방침 (/privacy)          ← 푸터에서만 연결
```

## 왜 이렇게 나눴나

**상단 메뉴는 3개 그룹뿐이다.** 처음엔 과정 소개・포트폴리오・후기・멘토 소개・커뮤니티・문의・공지 등을 전부 평면 메뉴로 나열했는데, 항목이 7~8개를 넘어가니 헤더가 복잡해졌다. "이 정보가 지원을 결정하는 데 필요한가(교육과정) / 학원과 소통하는 창구인가(소통공간) / 학원 자체에 대한 정보인가(학원안내)"라는 기준으로 다시 나누고 나니 항목이 자연스럽게 세 묶음으로 정리됐다. 데스크톱에서는 드롭다운(`NavDropdown.jsx`)으로, 모바일에서는 같은 세 그룹이 아이콘과 함께 펼쳐지는 드로어 메뉴(`Header.jsx`)로 구현했다 — 화면 크기만 다를 뿐 정보 구조 자체는 동일하게 유지했다.

**로그인 여부에 따라 같은 메뉴라도 보이는 게 다르다.** 소통공간의 문의하기・커뮤니티・공지사항은 로그인 없이도 목록을 볼 수 있지만, 실제로 글을 쓰거나 댓글을 남기려면 로그인이 필요하다. 이건 예비 지원자(비회원)가 결정을 내리기 전에 정보부터 충분히 살펴볼 수 있게 하려는 의도다. 반대로 상담 신청과 마이페이지는 시작부터 로그인을 요구하는데, 개인 이력과 연결돼야 의미가 있는 기능이라 접근 자체를 막는 게 맞다고 판단했다.

**역할별 영역(멘토/관리자)은 같은 계층에 있지만 서로 안 보인다.** `RequireAuth`가 `role`을 정확히 일치시키는 방식이라, 관리자 계정으로 멘토 대시보드에 들어가려 하면 "접근 권한이 없습니다"만 뜬다. 관리자와 멘토가 하는 일이 겹치지 않아서, 굳이 관리자에게 멘토 화면 접근을 열어줄 이유가 없었다.

**마이페이지는 사실상 지원자 전용의 "내 활동 허브"다.** 지원 현황・상담 현황・문의 내역・커뮤니티 활동을 각각 다른 곳에서 만들었는데, 결국 한 사람이 여러 기능을 동시에 쓰다 보니 "내가 지금까지 뭘 했는지"를 한곳에서 보고 싶어 할 거라 판단해 탭으로 묶었다. 처음엔 요약 카드를 기능별로 8개나 늘어놨는데, 너무 산만하다는 피드백을 받고 지원/상담/문의 3개 그룹으로 다시 압축했다.
